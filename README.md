# 民间借贷起诉状字段配置初版

版本 0.1.0，依据本次上传的民间借贷起诉状示例和用户提供的组织JSON结构建立。包含9个顶层模块、160条按角色及category展开的可填字段配置、15组枚举。原告、被告、第三人分别复用自然人和组织两个结构。160不是单个案件需要填写的字段数，不含固定category、结构容器及运行参数。

## 字段层次

| 顶层键 | 结构 | 对应原文 |
| --- | --- | --- |
| 原告 | 当事人数组或null | 自然人、法人和非法人组织栏 |
| 被告 | 当事人数组或null | 自然人、法人和非法人组织栏 |
| 第三人 | 当事人数组或null | 自然人、法人和非法人组织栏 |
| 委托诉讼代理人 | 总状态和代理人数组 | 有无、姓名、单位、职务、电话、权限 |
| 诉讼请求 | 固定对象 | 自由文本及第1至8项 |
| 约定管辖和诉前保全 | 固定对象 | 第1至2项 |
| 事实与理由 | 固定对象 | 自由文本及第1至18项 |
| 对纠纷解决方式的意愿 | 固定对象 | 1个总体了解、5个分项了解、1个意愿 |
| 签署信息 | 固定对象 | 具状人及日期 |

原文中的说明、特别提示及固定告知内容属于模板配置，不作为案件事实输出。事实与理由和诉讼请求的自由文本保留，与结构化分项并存，防止细分字段遗漏信息。

## 版本约定

1. 正式业务结果不携带每个字段的example、style或description。这些保存在配置和Schema。
2. category仅表示自然人或法人、非法人组织，不表示原告被告身份。主体角色由顶层键表示。
3. 所有固定结构对象和其属性均出现。未知叶子值为null；未知或无实际记录的重复数组为null；数组非空时至少一项，禁止空数组和null数组元素。
4. 明确否定保存否或无，不保存null。没有勾选任何选项且无正文依据保存null，不能填否。
5. 数据对象内各字段也固定出现并允许null；实际没有组织记录时不输出一个全空组织占位对象。
6. 金额按元保存两位小数的十进制字符串，内部运算使用Decimal。这是初步接口约定，并非原文已指定类型。
7. 完整日期为YYYY-MM-DD。不完整日期不补日；如2026年3月底前，保留期限原文，完整截止日为null。其他不完整日期在review保留原文。
8. 保持用户指定phone为字符串；多个号码保留原分隔符和顺序。未来改数组需版本变更。
9. 用户指定的registrationPlace只映射注册地或登记地；新增residence对应住所地或主要办事机构所在地，不相互补齐。
10. ownership主值规范为国有、民营、其他；其他内容放ownershipOther。用户例子其他集体所有制被规范为其他加集体所有制，此规则需要对接确认。
11. 所有制国有子选项集中保存在stateOwnershipType数组，只允许ownership为国有时非空。
12. 保留原文分项编号与标签，清除排版空格。英文自然人字段、细分子字段及调解五项简写键是本版建立的映射，不声称原模板已经存在这些JSON键。
13. 人工内部主体ID只出现在review或处理上下文，不加入正式当事人输出。
14. 固定结构存在不代表对应事项存在。保证合同对象保留且是否签订为否时，其其余值为null。

## 勾选组与条件约束

不能把所有方框视为多选。性别、是否、有无、代理权限、利率周期、单份保证方式和调解每个独立问题采用单选。组织类型包含组织形式和上市状态，按多选保存。

同组多选保存在一个数组，items限制合法枚举，uniqueItems去重，minItems设1，整体允许null。不要拆成每个选项一个布尔字段。

模板没有明示提前还款与解除合同、还款方式、登记类型、国有控股与参股的全部互斥规则。初版暂按多选保留，配置中列为待确认；Schema通过不代表这些选择在法律或业务上可同时成立。多担保物、多份保证合同和不同代理委托关系仍需后续确认重复记录粒度。

其他说明非空时，必须选择其他。选择其他但没有具体说明时，说明仍可为null，必要时进入人工复核，不能强制模型编造说明。国有子选项同理。

明确否时，已配置的条件详情须为null。选择是但未提供详情时，允许详情为null，业务校验可以提示缺失。不要用强制详情非空规则逼模型编造。

## 样例中的重要判断

- 仅输出自然人原告金洲及自然人被告赵月；法人和第三人空白栏不生成记录。
- 代理人有与无均未选，是否委托为null；不能当成无。
- 本金50000.00、利息320.83和标的总额50320.83直接按原文提取；只验证两项相加，不验证利息计算本身。
- 提前还款、解除合同、担保权利主张、管辖约定和已经诉前保全的选择均未填写，保留null。事实中相关担保否定勾选不能直接代填诉请担保权利主张。
- 正文明确2025年12月7日工商银行转账50000元，可填实际提供金额、提供方式和借款提供时间，尽管细分栏空白。银行名称保留在事实原文中，不新增正式银行字段。
- 正文明示现还款期限已过，可填是否到期为是。月底前承诺保留原文，不自动补成3月31日，也不把4月1日利息起算日直接填成逾期起始日。
- 诉请按一年期LPR计算不是合同约定借款利率；约定利率仍为null，也不查询外部LPR。
- 无书面合同不等于无借贷关系或无口头约定。
- 诉讼费用（保全费用，如有）保留条件，不能推出已经申请保全。
- 未填写已还本金、已还利息，不自动填0。至今已逾期的固定未完成提示不作为逾期时长。
- 正文提到录音不自动生成正式证据清单、证据名称或编号。
- 五个担保相关否选项和七个调解选项按实际勾选处理，落款和日期保持null。
- 法律条文仅转录附件，不在本任务验证其当前效力及适用。

## 抽取实现路径

1. 接收同一案件的fileContext、templateId、schemaVersion。多个列表项是否同案需要在接口中固定约定，不能混合不同案件。
2. 上游保留表格标签、段落与勾选状态。来源DOCX含Wingdings符号和文本字形；00FE为本附件已选框，00A8为未选框。只有确认字体和编码来源后才可转换þ、¨，不能做全局字符替换。
3. 对解析结果建立带来源的主体索引，明确原告、被告、第三人、法定代表人与代理人及委托关系。不能因为某人是担保人就自动创建为第三人。
4. 读取field_config.json，按模块投影相应Schema和description，加入共享主体索引。四任务为当事人、诉请、事实、剩余内容；字段多时将事实原文和1至9项、10至18项分为两任务。
5. 模型输出各自负责的字段，未知值null，不越权新增字段。JSON Schema只能约束结构，是否缺失、属于谁、是否明确否定仍依赖提示词和业务验证。
6. 使用共享4至5线程工作池、有界提交队列和跨请求模型调用配额。主体索引及重试也受配额约束。多实例需要共享配额，线程数不等于全局限流。
7. 程序按字段路径和内部主体ID合并，不能让任务按完成先后覆盖数据。每个最终字段只有一个负责模块。
8. 后端始终使用本版完整Schema校验，并显式启用日期FormatChecker；date的format在未启用格式检查时不能保证日历合法。
9. 业务校验区分尚欠本金、实际提供金额和约定金额，检查主体关联、日期含义、条件事项及不同来源冲突。冲突返回null并把候选值和来源写review，不自行选较大金额或最新一句。
10. 格式或类型问题有限重试；事实缺失、冲突和上游丢失勾选状态进入复核。超时或调用失败不得填成业务缺失后冒充成功。
11. 对外按需只返回业务JSON，review通过请求ID关联。记录Schema、配置、提示词和模型版本。

推荐最小技术栈：Python 3.12、FastAPI、模型官方SDK、jsonschema、Decimal、ThreadPoolExecutor。Pydantic用于接口模型可选；Redis用于多实例配额按部署需要增加。首版无需向量库和复杂Agent框架。

不同模型的结构化输出只支持JSON Schema的不同子集，尤其oneOf、allOf、if/then和条件组合需逐一验证。可以生成供应商专用投影Schema，但不得因此取消完整后端校验；投影规则与完整Schema需共同回归。

## 校验及复现

验证：先执行 `pip install -r requirements.txt`，再执行 `python validate.py`。实际报告见validation_report.json。测试覆盖category与data错配、空数组、非法枚举、多选重复、条件详情、日期及金额类型。不能用这些结构测试宣称模型抽取准确率。

重新生成配置：`requirements.txt` 已包含构建所需的 lxml；将源DOCX放在本目录上一级upload中，执行 `python build_fields.py`，再执行 `python validate.py`。读取Schema、字段配置和样例无需源DOCX，也不需要运行生成脚本。

本版fieldId按初次展开顺序生成。进入正式使用后应冻结已有ID并以显式ID映射维护，新增字段不能重新编号；字段路径与版本是当前对接依据。
